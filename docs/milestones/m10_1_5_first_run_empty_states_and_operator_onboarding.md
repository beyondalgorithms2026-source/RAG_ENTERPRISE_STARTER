# M10.1.5 — First-Run Empty States And Operator Onboarding

- Reworked the clean-DB user workspace experience so Chat, Search, History, and Sources now explain what happens first instead of reading like missing data or broken UI.
- Added stronger first-run guidance for uploads and retrieval readiness, including clearer distinctions between upload accepted, indexing still running, retrieval returning no visible match, and answer generation still in progress.
- Replaced the misleading workspace storage sidebar card with truthful first-run guidance that points users toward uploads, indexing readiness, and the first grounded chat/search run.
- Added an operator first-run checklist in the admin overview and tightened corpora, jobs, evals, and traces empty states so loading, no data yet, and no activity yet are visibly different.
- Clarified admin next steps for first corpus creation, first source placement, first queued job, first trace, and first eval so a clean install feels intentionally empty rather than unfinished.
